# sops_entry (Resource)

Manage specific key/value entries in an existing SOPS-encrypted file. Inserts entries if missing, updates if changed. Unchanged values preserve their ciphertext via SOPS IV stash mechanism.

Changing the `file` path forces resource recreation, which removes managed keys from the old file and writes them to the new file.

On `terraform destroy`, managed keys are removed from the file. Other keys are left untouched.

## Example Usage

```terraform
provider "sops" {}

resource "sops_entry" "secrets" {
  file = "config.enc.yaml"

  entries = {
    db_password    = var.db_password
    api_key        = var.api_key
    redis_password = var.redis_password
  }
}

# Nested keys use dot-separated paths
resource "sops_entry" "nested" {
  file = "config.enc.yaml"

  entries = {
    "database.password" = var.db_password
    "database.port"     = "5432"
  }
}

output "all_config" {
  value     = resource.sops_entry.secrets.data
  sensitive = true
}
```

## Import

Resources can be imported using the file path:

```shell
terraform import sops_entry.secrets config.enc.yaml
```

After import, run `terraform plan` to sync entries from your configuration.

## Schema

### Required

- `file` (String) Path to an existing SOPS-encrypted file. Changing this forces resource recreation.
- `entries` (Map of String, Sensitive) Key/value pairs to set in the encrypted file. Keys support dot-separated paths for nested access (e.g., `db.password`). Numeric path segments are treated as array indices.

### Read-Only

- `id` (String) Resource identifier (set to the file path).
- `data` (Map of String, Sensitive) All decrypted key/value pairs from the file after update.

## Limitations

- **One resource per file**: Only one `sops_entry` resource should target a given file. Multiple resources writing to the same file will race and may lose data.
- **Single YAML document**: Only the first document in multi-document YAML files (separated by `---`) is supported.
- **Numeric string keys**: YAML keys that are purely numeric (e.g., `"8080"`) cannot be targeted because they are interpreted as array indices. Use the SOPS CLI for such keys.
